# ADR-0001：独立守护进程，直连 V2 事件流，不写插件

**状态**：已接受

## 背景

V1 的做法是 OpenCode 插件（TypeScript）持有状态机，另拉一个 Python 托盘子进程负责弹通知。
V2 版重新选择形态。

## 决策

做成**独立守护进程**：读取 `service.json` 发现本机服务，用 Basic 认证（用户名 `opencode`）订阅 `GET /api/event` 事件流，自持全部状态。不写插件。

## 理由

- 与 OpenCode 解耦：可独立重启、测试、发布；插件 API 再变（V1→V2 已换过一次）也与我们无关。
- 插件位置没有额外能力：灯和通知都只需要旁听事件。
- 事件流是“易失”的（慢消费者会断、断开期间会丢事件）；但重连 + 用 REST 重建状态是薄薄一层，成本低。

## 代价

- 自行实现：服务发现、鉴权、断线重连、状态重建。
- 生命周期独立：OpenCode 没开时守护也在跑（空闲，无事可做）。
