# ADR-0004：键盘访问策略——唯一写者、独占打开、避让官方程序

**状态**：已接受（2026-10-27 修订：2.4G 通道已接入，见 ADR-0007）

## 决策

- **同一时刻唯一写者**（沿用 leobog 红线）：独占打开设备；`OemDrv.exe`（官方程序）在跑就完全不碰设备；
  只写实时数据对象 `0x08`；发包前四项特征（VID、PID、UsagePage、特征报告长度）全部核对；
  一次失败即停，不循环重试。
- **两种通道，一条红线**：有线走 520 字节特征报告；2.4G 走接收器的 27 包 378 字节缓冲。
  两条都遵守「唯一写者」——同一把键盘只允许一条通道在写。
- **不与其他灯效软件联动**：不检测、不联动、不让路。两边同时开着时的写入争抢由用户手动处理
  （已知并接受）。唯一例外是上面那条对官方程序的避让。

## 理由

键盘有变砖级前科（OpenRGB 曾误伤同控制器的键盘）。HID 通道宁保守勿聪明；
外部灯效软件的集成没有需求，只有维护负担与风险。

## 2026-10-27 修订说明

原决策写的是「仅支持有线」，理由是 2.4G 接收器的特征报告只有 8 字节，物理上发不出一帧灯光。
这个判断后来被推翻：接收器虽然有 8 字节特征报告，但**它同时是一条输出报告通道**，
可以分 27 包发送完整的 378 字节颜色缓冲（逐包 ACK）。实测可行，细节见
`docs/2.4G-LED-验证记录.md`，发送时机见 ADR-0007。
