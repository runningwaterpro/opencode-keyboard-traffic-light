# ADR-0002：灯态语义——紫=执行中、红=失败、黄=等待、绿=完成确认（30 秒）；只有黄呼吸

**状态**：已接受

## 决策

- 三态 + 一次确认：**执行中=不亮（键盘）**、失败=红、等待=黄（呼吸）、完成=绿；其余时间灯灭。只有黄持续呼吸。
- 并存优先级（同一会话多状态叠加时）：**黄 > 红 > 执行中 > 绿**；红保持到该会话下次开跑（变紫→不亮）或成功（亮绿）。
- 绿是**事件**不是状态：成功才亮；未运行过的会话、静默中断（`user`/`superseded`）、守护重启或重连重建出的空闲会话都不点绿。
- 2026-10-26 修订：绿原表示「空闲」，现改为「完成确认」——空闲不再亮灯，避免把「没在跑」误读成「刚做完」。
- 2026-10-27 修订：**执行中不点亮**。紫亮着的时候用户没有任何动作可做，只是占用视觉带宽；亮久了用户会学会无视整把键盘，真有事时反而看不见。执行中仍然是一个 `Light.RUNNING` 状态（托盘继续显示），只是键盘渲染时不落色（`frame.render_slots` 跳过）。
- 2026-10-27 修订：**显示时长有了上限**，且只作用于键盘，托盘（`state.display`）不受限：
  - 黄最长 10 分钟（`WAITING_MAX_MS`）——覆盖「短暂分心」的上界；超过就是离岗，交给托盘。
  - 红最长 5 分钟（`FAILED_MAX_MS`）——红是一次性事件，只需覆盖一次回头；再长会让键盘长期挂红。
  - 绿 30 秒 → 60 秒（`IDLE_VISIBLE_MS`）——30 秒切回窗口常常已经灭了。
  - 分工：**键盘负责打断（短、强、会消失），托盘负责记账（长期、静止、可回查）**。
- 黄 = 有未处理的权限请求或提问，处理完才变；权限瞬间被自动放行时也保底可见一小段（时长实现时定）。
- 中断细分（事件自带原因）：**`user`（按 Esc 等主动取消）、`superseded`（被新的执行顶掉）→ 不算失败：不红、不通知**；`failed`（真失败）及 `shutdown`/`inactivity` → 按未完成处理：红 + 通知。

## 理由

按“要你付出多少关注”排：绿=什么都别管，紫=在跑但别管，红=记一笔没跑完，黄=现在就差你。唯一的动态（呼吸）留给唯一“要你动手”的状态。
“我知道我按的取消”——用户主动的取消不打扰。
